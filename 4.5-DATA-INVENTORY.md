# Group 4.5 — Production vs Demo Data Inventory (+ demo-data plan)

**Purpose:** track exactly which data in the live DB is **real/production** (must never be fabricated
over or lost) vs **demo/seed** (safe to reset), so fake data for a demo can be layered on **around**
the real masters without corrupting them. Sits between Group 4 and Group 5.

**As of 2026-08-17**, derived by querying the live Turso dev DB directly (`.env.local`'s `TURSO_URL`
— the shared cloud DB, not the 0-byte local file). Re-run the inventory before a demo if time has
passed; the counts below are a point-in-time snapshot. **This revision supersedes the 2026-08-04
snapshot below it — the demo project set was fully wiped and rebuilt on this date** (see "2026-08-17
rebuild" below).

---

## The one golden rule

> **`suppliers` (445 rows) is real client data. Everything else is demo/seed, an accumulating
> master, or empty.** Never re-fabricate suppliers, and remember any *supplier master re-import
> wipes `supplier_quotes` + `purchase_orders`** (see "Wipe gotcha" below).

## 2026-08-17 rebuild — what changed and why

All per-project/demo data (the old `projects` 3/4/5/6/SB-1018 set, their BOM, QC, packing, tasks,
notifications) was deliberately wiped and rebuilt as `scripts/seed-demo-pipeline.mjs`, confirmed
with the user first (all of it was test data, nothing real). The goal was 3 projects that each sit
at one clear, distinct pipeline stage — Lead through Sale Order with no project yet, mid-build with
Design in progress, and near-complete — instead of a set of demo projects that all looked roughly
the same. Full design context: session notes and `PRODUCTION-MODULE-DESIGN.md`.

**Left untouched by the wipe** (config/masters, same treatment as `suppliers`): `users`, `employees`,
`operations`, `workstations`, `trades`, `stage_templates`/`stage_template_items`,
`calc_formulas`/`calc_formula_versions`/`calc_formula_tests`/`calc_tables`/`calc_table_rows`/
`calc_validations`/`calc_templates` (global engineering methodology, not project data), `suppliers`,
`counters`, `holidays`, `system_migrations`.

**Also left untouched, but reclassified below:** `customers`. The 2026-08-04 snapshot called this
"MASTER READY, NOT LOADED" at 0 rows. It is no longer empty — Sales/CRM shipped since then and the
table now behaves as an accumulating master, the same pattern as `suppliers`: the new seed script
never deletes it, and reuses an existing row by name (`getOrCreateCustomer`) instead of erroring on
the `UNIQUE(name)` constraint. It currently holds 3 rows, all created by the rebuild.

## Gaps introduced or left open by the 2026-08-17 rebuild

Reporting these rather than fixing them — each is real, scoped work, not something to silently patch
in passing:

1. **`scripts/seed-procurement-demo.mjs` is now stale and will error if run.** It hardcodes
   `PROJECTS = [3, 4, 5, 6]` — the old project ids, all deleted by the rebuild. Running it today
   would either no-op (`WHERE project_id IN (3,4,5,6)` deletes on the wipe step, matches nothing) or
   fail outright depending on the exact statement. **Effect: Procurement's Sourcing, Selection, and
   Purchase Orders tabs currently have nothing to show** — 0 quotes, 0 POs, 0 comparison data,
   whereas before the rebuild there were 24 quotes and 2 multi-project POs specifically built to
   demo that flow. Fixing this means either pointing that script at the new project ids (13, 14) or
   rewriting it to look projects up by `project_no` instead of a hardcoded array — real work, not
   attempted here.
2. **QC's Certificate bank and statutory document demo shrank sharply.** Before: 17 test certificates
   (real-derived from the client's actual SB-1037 sample) and a 216-part Form IV A document. Now: 2
   certificates and a 2-part document, built fresh for this rebuild's narrower "near-complete
   project" story. QC's own workspace will look much thinner in a demo than it did two weeks ago.
3. **Dispatch's packing demo shrank.** Before: 2 packing lists, 137 items. Now: 1 list, 5 items.
4. **Workflow Stages (`milestone_stages`) has zero rows.** The rebuild's milestone-seeding is a
   simplified, explicit version (see the script's own comment) that does not call
   `copyDefaultStageTemplate`, unlike the app's own `createProjectMilestones`. Any milestone on
   either of the 2 rebuilt projects will show an empty Stages checklist even where the real app would
   normally auto-copy a default template.
5. **Calc Sheets have no seeded `calc_variables` rows for the 2 new projects**, unlike the original
   app-seeded SB-1018 sheet. The Calculation screen still renders (it falls back to library defaults
   when a sheet has no rows of its own), so this isn't visibly broken, but a snapshot/history story on
   these sheets would be thin if someone tried to demo that specifically.
6. **`tasks` (Incidents demo, Outgoing/Incoming) is empty**, was 16 rows before. Out of scope for
   this rebuild (it targeted the sales-through-dispatch pipeline story, not Operations' incident
   cards), not rebuilt.

None of these are urgent — the rebuild's actual goal (a clean, distinct-stage Lead→Sale
Order→Project→Design→BOM→QC→Job Cards→Packing walkthrough, plus the new customer drawing-approval
feature) is intact and browser-verified end to end. These are the corners that got thinner as a
side effect, worth knowing about before anyone demos Procurement, QC's certificate bank, Dispatch,
or Workflow Stages specifically.

## Wipe gotcha (ordering constraint for any demo seed)

`POST /api/masters/suppliers/import` does a **full replace** and clears `purchase_orders` +
`supplier_quotes` first (FK-safe, client-accepted). So:
- **If you re-run the supplier import live during a demo, it deletes any fake quotes/POs.**
- **Correct order:** load/settle suppliers **first**, then create fake procurement activity **on
  top**.
- The same principle now applies to `scripts/seed-demo-pipeline.mjs`: it never touches `suppliers`,
  `customers`, `employees`, or any other master, by design — same precedent as the retired
  `seed-procurement-demo.mjs` script it partly supersedes.
