## Two accuracy corrections (things that aren't what they seem)

1. **Only ONE of the three masters is actually loaded.** You imported all three files, but only
   **suppliers** hit the DB (445 rows, all with the real party columns). **`customers` = 0 and
   `items` = 0** — they were parsed/verified (Group 3) but never written, because there's no UI
   surface to trigger their import yet (Sales dept / item catalog don't exist — Groups 6/later). The
   `POST /api/masters/customers|items/import` route + parser are ready; they just need to be called
   (a script, or a temporary admin button) to load. **For the current demo they show as empty tables.**

2. **The supplier import wiped the demo's procurement activity — now RESTORED (2026-08-04).**
   `supplier_quotes`, `purchase_orders`, `po_items` were all 0 after the vendor import's full-replace.
   **Rebuilt** via `scripts/seed-procurement-demo.mjs`, now updated to **preserve the 445 real
   suppliers** (picks real ones by category keyword — steel/valve/pump — as the demo vendors, never
   wipes the master). Current state: **24 quotes** (all referencing real suppliers), **2 POs** (1
   draft + 1 issued, both spanning all 4 projects → show "Multiple" in the Group-4a column), full
   item-status spread (sourcing → comparing → transit → received → closed → cancelled), 0 dangling
   references. **Re-run any time:** `node --env-file=.env.local scripts/seed-procurement-demo.mjs`
   (idempotent for its own rows; safe — never touches the supplier master). **Re-run it AFTER any
   supplier re-import**, per the wipe gotcha below.

## Wipe gotcha (ordering constraint for any demo seed)

`POST /api/masters/suppliers/import` does a **full replace** and clears `purchase_orders` +
`supplier_quotes` first (FK-safe, client-accepted). So:
- **If you re-run the supplier import live during a demo, it deletes any fake quotes/POs.**
- **Correct order:** load/settle suppliers **first**, then create fake procurement activity **on top**.
- If you want to *show* the supplier import as part of the demo, do it **before** seeding fake
  quotes/POs, or re-seed activity afterward.

## Demo-data plan — fake activity to layer on the real 445 suppliers ✅ DONE (2026-08-04)

**Built and run** via `scripts/seed-procurement-demo.mjs` (updated to preserve the real master). The
spec below is what it produces; it's re-runnable. Goal: make `/procurement`, Operations' Procurement
flow, and the project pages look alive, using the **real** supplier names, without touching the
445-row master. All of it references real `suppliers.id` and the demo `bom_items` — additive, no
schema change.

1. **Quotes** (`supplier_quotes`): for a spread of the 37 demo BOM items, log 1–3 quotes each from a
   handful of the real suppliers (varied price / payment terms / expected-delivery date so "Lowest
   price" and "Fastest delivery" badges light up). Reference real `supplier_id`s.
2. **Selections → draft POs**: select a supplier on a subset of items (drives the auto-draft-PO), so
   the Selection tab shows picks and the PO tab shows drafts — **include at least one PO that spans
   two projects** so the new Group-4a "Multiple" column demos.
3. **Issued / in-transit / closed**: issue a couple of POs (→ TRANSIT) and mark a few items CLOSED, so
   the pipeline shows realistic spread across all stages, not everything in "Sourcing."
4. **Keep** the existing demo requests (8) + tasks/incidents (16) — they already populate the Requests
   tab and the new Operations incident cards.
5. **Optional:** load `customers` (332) + `items` (2,773) via the ready import routes if you want the
   master data present — but note **nothing renders them yet** (no Sales/item-catalog UI), so it only
   matters if you're demoing the raw import or preparing for Groups 5/6. Skip for a procurement-focused
   demo.

**Build it as a re-runnable seed script** (idempotent, references real supplier ids by name-lookup so
it survives a supplier re-import) rather than one-off inserts — same "reseedable demo" spirit as D18.
Not built yet; this doc is the spec.
