# Compact instructions

When compacting context, preserve:

- Current feature/workflow being implemented
- Files changed and why
- Database/schema changes
- API routes and contracts
- Business rules and edge cases
- Important test results
- Known bugs and unresolved decisions
- Important production/live-data findings

Discard:
- Repeated explanations
- Failed exploratory approaches
- Old conversation details
- Redundant command output
